# COVERED Studio - Phase 4 design contract

Status: binding for units A, B, C, D. Written by the architect on branch `phase4/design`.
If this file and your idea disagree, this file wins. If it is wrong or silent, make the smallest decision that keeps
the interfaces below intact and record it in your unit's README section "Deviations" (do not edit this file during the
build; the integrator folds deviations back).

Goal: on a preview build (`CMS_EDIT=1`) a founder clicks a headline, edits it in place, swaps a photo, hides a section
(from a phone too); edits are staged in the browser and saved as ONE validated patch to a DRAFT BRANCH + PULL REQUEST
through a small API; a History panel lists merged changes and Restore opens a revert PR; own login with roles;
onboarding and a command palette. Production HTML stays byte-identical.

Conventions: Node >= 22, CommonJS (`require`) everywhere except the two adapter files that must be ESM (`.mjs`); no new
runtime dependency (section 13); existing files keep their CRLF/LF (targeted edits), new files LF; tests use `node:test` +
`node:assert/strict`; times are ISO-8601 UTC strings; JSON is UTF-8.

## 0. Decisions in one screen

| # | Decision |
|---|---|
| D1 | The overlay is plain JS, shipped only in `CMS_EDIT=1` builds at `/studio/overlay.js` (+ `/studio/content.json`), injected by ONE `<script>` tag. It is inert unless the URL has `?studio=1` (then remembered per tab in `sessionStorage`). |
| D2 | Markers come from one Nunjucks shortcode `{% cms ref, kind, opts %}` that returns `""` unless `CMS_EDIT=1`. Normal builds are byte-identical (guard, 3.4e). |
| D3 | Single source of truth for rules is `cms/config.yml`. `studio/schema/studio-schema.json` is generated from it (committed, freshness-checked). Rules that live in code (safeUrl, safeColor, anchors, tokens, redirects, image/SVG/EXIF) are extracted once into shared modules that BOTH the Eleventy filters and the API import. |
| D4 | Patch = RFC 6902 subset (`replace add remove move` + optional `expect`), scoped per file, plus image uploads inline (base64), atomic, idempotent. Only `src/_data/*.json`, `src/pages/*.md` and new files in `images/` can be touched. |
| D5 | API = one pure `(Request) => Promise<Response>` handler + three adapters (Node http, Netlify Functions v2, Cloudflare Workers). Auth by `Authorization: Bearer` only; no cookies; no wildcard CORS. |
| D6 | Auth = Supabase Auth JWT verified locally with WebCrypto (HS256 secret, or RS256/ES256 via JWKS). Roles come from table `studio_roles`, read with the caller's own JWT under RLS (the API never holds a Supabase service key). |
| D7 | Git = GitHub App installation token (least privilege) via the Git Data API. Every write goes to `studio/*` branches; merge only through the PR merge endpoint after checks are green. |
| D8 | Everything external sits behind provider interfaces with (a) a real implementation written to the public API (never run against the live service by us) and (b) a local/mock one used by all tests. |
| D9 | "Hide a section from a phone" is read as: the founder can do it ON a phone (responsive overlay, toggling a homepage section's `enabled` switch). No per-device visibility field is introduced (needs a new CMS field + CSS: out of scope). |
| D10 | Live Netlify previews currently return 401, so the primary way to run and demo Studio is `npm run studio:dev` (local `CMS_EDIT=1` build + mock Git + dev auth; no accounts). Hosted use needs Teo's manual steps (section 17). |

## 2. Marker grammar (unit A)

### 2.1 Reference string ("ref")
```
ref   := file ("." seg)+
file  := dataStem | "pages:" pageSlug      dataStem = [a-z][a-z0-9-]*  (src/_data/<dataStem>.json)
                                           pageSlug = [a-z0-9-]+       (src/pages/<pageSlug>.md)
seg   := [A-Za-z0-9_-]+                     object key, array index (digits), or the reserved seg "_body"
```
Examples: `hero.headlineMain`, `how.story.2.title`, `homepage.sections.3`, `homepage.sections.3.enabled`,
`nav.items.1.label`, `pages:about.title`, `pages:about.sections.1.heading`, `pages:about._body`.
`_body` is the markdown body of a page (front matter keys never start with `_`; the schema build fails if one does).
No data key may contain `.` or characters outside `seg` (true today; the schema build enforces it). Max ref length 160.

`studio/markers/grammar.js` exports:
```
parseRef(str)         -> { file: "how" | "pages:about", segs: ["story","2","title"] } | null     // null = invalid; never throws
formatRef(file, segs) -> str                                                                       // throws on invalid input
locate(ref)           -> { filePath: "src/_data/how.json" | "src/pages/about.md", kind: "data"|"page", pointer: "/story/2/title" }
REF_RE                                                                                             // the exact regexp for attribute checks
```
Pointer = `"/" + segs.join("/")` (segments contain neither `~` nor `/`). A page's front matter is the root object; its body is `/_body`.

### 2.2 Attributes and kinds
`{% cms "<ref>", "<kind>" %}` or `{% cms "<ref>", "<kind>", { alt: "<ref>", ... } %}` goes INSIDE the tag (after the last
attribute, before `>`):
```njk
<h2 class="section-title" id="how-title"{% cms "how.title", "text" %}>{{ how.title }}</h2>
<figure class="story-card"{% cms "how.story." + loop.index0, "item" %}> ... <strong{% cms "how.story." + loop.index0 + ".title", "text" %}>
```
Emitted (edit builds only), always in this order; every value is validated (refs against `REF_RE`, cssvar against `--[a-z0-9-]+`),
otherwise the whole shortcode returns `""` and the guard fails the build (fail closed):

| attribute | meaning |
|---|---|
| `data-cms="REF"` | the value this element shows |
| `data-cms-kind="KIND"` | `text` (string, single line) · `longtext` (text widget) · `markdown` (element shows rendered HTML) · `image` · `link` · `color` · `toggle` (boolean) · `section` (homepage section wrapper; REF = `homepage.sections.N`, toggles its `.enabled`) · `item` (one element of a list: delete / move / duplicate) |
| `data-cms-alt="REF"` | image: ref of its description; presence means "ask for alt text" |
| `data-cms-decorative="REF"` | image: ref of the "decorative picture" boolean |
| `data-cms-href="REF"` | element is or sits in an `<a>`: ref of the link target (a field with x.rule `url`) |
| `data-cms-hide="REF"` | ref of a boolean whose `false` hides this element (a switch other than `enabled`) |
| `data-cms-cssvar="--name"` | color: `:root` custom property receiving the colour for live preview |

`opts` keys are exactly `alt, decorative, href, hide, cssvar`; anything else => `""` + guard failure.
Kind <-> widget compatibility (A's guard enforces; B's validator re-derives everything from the schema, never from markers):
`text<-string`, `longtext<-text`, `markdown<-markdown`, `image<-image`, `link<-string with x.rule url`, `color<-color`,
`toggle<-boolean`, `section<-homepage list item`, `item<-any list item`.

Template rules (A): put the marker on the element that owns the value; a value shown twice gets two markers; list items get
`item` on the wrapper and field markers inside. The `<section>` of EVERY section partial in `src/_includes/sections/*.njk`
carries `{% cms "homepage.sections." + secIdx, "section" %}`, with `{% set secIdx = loop.index0 %}` added in the loop of
`src/index.njk` (the `set` prints nothing). Page templates use
`{% cms "pages:" + page.fileSlug + ".sections." + loop.index0 + ".heading", "text" %}`. Text sharing an element with other elements
(`<h1>text <span class="accent">accent</span></h1>`) gets a marker on the h1 (first string) and one on the span. Values that are not visible text
(aria-labels, meta) get no marker; they are reachable through the Fields panel (C). **No ref may be built from DATA values**, only
literals, loop indices and `page.fileSlug` (guard-enforced).

### 2.3 Zero effect on production
`cms` is `eleventyConfig.addShortcode("cms", fn)` in `lib/eleventy/studio.js`; when `process.env.CMS_EDIT !== "1"` it returns `""`
before doing anything. In a normal build the plugin registers nothing else (no transform, no files). `htmlmin` is unchanged.

## 3. Build outputs of an edit build (unit A)

With `CMS_EDIT=1` (and only then) `lib/eleventy/studio.js`:
1. **Injects one tag** before `</body>` of every HTML page with a transform registered after `htmlmin` (plugins load after `.eleventy.js`, so a plain string replace on the minified HTML):
   `<script src="/studio/overlay.js" defer data-studio data-api="<STUDIO_API_URL>" data-app="<STUDIO_APP_URL>" data-content="/studio/content.json"></script>`
   `STUDIO_API_URL` / `STUDIO_APP_URL` must be `https://...` or `http://localhost[:port]` / `http://127.0.0.1[:port]`, otherwise the build fails; unset => attribute omitted (the overlay then runs "unconfigured": panel explains how to configure, dev server works because it sets them).
2. **Writes `/studio/overlay.js`** = `require("../../studio/overlay/bundle.js").bundle()`; if that module is missing (C not merged yet) write a stub that sets `window.CoveredStudioMissing = true` and print a warning.
3. **Writes `/studio/content.json`** (`snapshot.js`):
```json
{
  "schemaVersion": 1,
  "build": { "sha": "<40 hex or null>", "branch": "<name or null>", "builtAt": "ISO", "prNumber": null },
  "schemaSha256": "<configSha256 from studio-schema.json>",
  "files": {
    "how":         { "path": "src/_data/how.json", "data": { } },
    "pages:about": { "path": "src/pages/about.md", "data": { "title": "About us", "_body": "markdown ..." } }
  }
}
```
   `sha`: first of `COMMIT_REF` (Netlify), `GITHUB_SHA`, `git rev-parse HEAD` (try/catch -> null). `branch`: `HEAD` (Netlify), `GITHUB_HEAD_REF`, `git branch --show-current`. `prNumber`: `REVIEW_ID` or null. The overlay treats `branch` starting with `studio/` as "this preview IS draft X".
4. **Guard `studio/guards/check-markers.js`** (A): builds a normal and a `CMS_EDIT=1` copy (via `scripts/lib/workspace.js`; pass `CMS_EDIT` explicitly to child builds) and proves:
   a. every `data-cms*` value parses, `locate()` finds the file in `studio-schema.json`, `resolve()` finds a field, kind and widget are compatible;
   b. **marker truth**: text/longtext: the element's own text equals the value in content.json (same normalisation as check-copy); image: file stem of the value appears in `src`/`srcset`; link: `href` equals `safeUrl(value)`;
   c. **coverage ratchet**: the (file, pointer) string leaves that check-copy's corpus traces to the built home page and `/about/` and that carry a marker are stored in `studio/schema/marker-coverage.json` (`--update`); the count may not shrink; unmarked ones are listed with `--warnings` as "Fields panel only";
   d. **hostile**: an edit build with attack strings in every field (reuse `scripts/lib/hostile.js`) has no new event-handler attribute, no `<script>` other than the overlay tag, and every marker value is unchanged (refs are literals + indices only);
   e. **parity** (the proof of the hard constraint): after deleting from the edit HTML every ` data-cms[a-z-]*="[^"]*"` attribute and the single overlay `<script ...></script>` tag, every HTML file is byte-identical to the normal build; every other shared file is byte-identical; the edit build has exactly two extra files (`studio/overlay.js`, `studio/content.json`); a normal build contains no `data-cms` and no `studio/` path.
5. `scripts/lib/util.js` (A, one line at the top): `delete process.env.CMS_EDIT;` so every existing guard builds production HTML even when the developer's shell has `CMS_EDIT=1`.
6. `netlify.toml` (A, append-only block at the end):
```toml
# Studio overlay only on pull-request previews. Production never sets CMS_EDIT.
[context.deploy-preview.environment]
  CMS_EDIT = "1"
[context.production.environment]
  CMS_EDIT = ""
```
   `STUDIO_API_URL` / `STUDIO_APP_URL` are set by Teo in the Netlify UI (17), never in files.

## 4. Generated schema (unit A)

`npm run studio:schema` writes `studio/schema/studio-schema.json` from `cms/config.yml` with `scripts/lib/cmsconfig.js` (js-yaml).
`studio/guards/check-schema.js` runs `--check` (committed file == fresh generation; deterministic, config order, 2-space JSON, LF) and
re-uses the `check:cms` walker to prove every data/front-matter key has a schema entry.
```jsonc
{
  "schemaVersion": 1,
  "configSha256": "<sha256 of cms/config.yml with CRLF normalised to LF>",
  "reservedIds": ["adbar", "bbudget"],                   // = lib/reserved-ids.js reservedIds(); check-schema keeps it equal
  "files": {
    "how": { "path": "src/_data/how.json", "kind": "data", "label": "...", "collection": "content", "fields": [ Field ] }
    // one entry per file of the "content" collection (homepage, site, theme, tokens, redirects, ...), key = ref `file` part
  },
  "pages": { "folder": "src/pages", "label": "Pages", "fields": [ Field ], "body": Field },   // all src/pages/*.md share one schema
  "limits": { "string": 20000, "markdown": 60000, "listItems": 200 }
}
```
`Field` = the config.yml field JSON-ified, nothing invented except `x`:
```jsonc
{
  "name": "headlineMain", "label": "...", "hint": "...",                 // hint verbatim
  "widget": "string",                                                      // defaulted when absent
  "required": true, "default": null,                                       // required defaulted true
  "pattern": { "source": "^...$", "message": "..." },                      // from pattern: [regex, message]; JS RegExp, no flags
  "min": 1, "max": 8, "valueType": "int",                                  // list item count / number bounds; number valueType int|float
  "options": [ { "label": "...", "value": "..." } ], "multiple": false,    // select
  "fields": [ Field ],                                                     // object
  "field": Field,                                                          // list of a single field
  "types": [ { "name": "hero", "label": "...", "fields": [ Field ] } ], "typeKey": "type",   // typed list
  "x": {                                                                   // derived from CODE; only where it applies
    "rule": "url|anchor|color|redirect-from|redirect-to|token|permalink|image",
    "imageStyle": "public-path|bare-name",                                 // x.rule image: value form, derived from its pattern
    "token": { "kind": "number|word", "min": 0, "max": 0, "step": 0, "words": ["motor"] },   // copied from lib/tokens.js TOKENS
    "list": { "reorder": true, "add": true, "remove": true }
  }
}
```
`x.rule` assignment: `url` when the pattern source equals the standard link pattern (`LINK_PATTERN_SOURCE` exported by B's `lib/rules.js`; until B lands A hard-codes the same string and the guard compares them); `anchor` for fields named `anchor` whose pattern embeds the reserved-id list; `color` for the color widget; `token` for fields below `tokens`; `redirect-from/to` for `redirects.items[].fromLink/toLink`; `permalink` for the pages `permalink`; `image` for the image widget.

`studio/schema/resolve.js` (UMD, no dependencies, Node + browser):
```
resolve(schema, fileKey, segs, doc) -> { field, parent, itemType, list, indexInList } | null    // typed-list item types chosen from doc; null = not allowed
labelFor(schema, fileKey, segs, doc) -> "Our story > Heading"                                   // plain-English breadcrumb (PR bodies, overlay, history)
fieldsAt(schema, fileKey, segs, doc)  -> [Field]                                                // children, for generated forms
```

## 5. Patch format (shared by B, C, D)

`POST /v1/drafts` body (`Content-Type: application/json; charset=utf-8`, <= `STUDIO_MAX_BODY_BYTES`, default 6,000,000):
```jsonc
{
  "idempotencyKey": "9b1c0e0e-5c8e-4f4e-8a55-0f6f6c5b2d11",   // UUID v4 from the client; REQUIRED on every write
  "draftId": "u7k2m9qa--summer-edits",                          // optional: omit to create a new draft
  "baseSha": "<40 hex>",                                        // main sha the overlay's build came from (content.json build.sha); REQUIRED when creating
  "expectedHeadSha": "<40 hex>",                                // REQUIRED when updating: draft head the client last saw
  "title": "Make the hero friendlier",                          // optional, <= 80 chars plain text; derived if absent
  "ops": [
    { "op": "replace", "file": "src/_data/hero.json", "path": "/headlineMain", "value": "We cover the UK", "expect": "We're covering the UK," },
    { "op": "replace", "file": "src/_data/homepage.json", "path": "/sections/4/enabled", "value": false, "expect": true },
    { "op": "move",    "file": "src/_data/homepage.json", "from": "/sections/6", "path": "/sections/2" },
    { "op": "add",     "file": "src/_data/faq.json", "path": "/items/-", "value": { "q": "...", "a": "..." } },
    { "op": "remove",  "file": "src/_data/how.json", "path": "/story/3", "expect": { } },
    { "op": "replace", "file": "src/pages/about.md", "path": "/_body", "value": "Markdown ...", "expect": "..." }
  ],
  "uploads": [ { "id": "u1", "name": "story-5-bathroom.jpg", "contentType": "image/jpeg", "size": 412345, "dataBase64": "..." } ]
}
```
* `file` is an allowlisted repo path (6.2). `path`/`from` are RFC 6901 pointers inside that file (page front matter is the root object, the body is `/_body`).
* Ops apply in order to a deep clone of the draft head (main head for a new draft); the first failing stage aborts everything (atomic: nothing is committed).
* `expect` = the value the client believed was there; deep-equal against the draft head before applying; mismatches => `409 conflict` listing ALL of them. The overlay always sends it.
* An image op's `value` has the field's own form (`"/images/x.jpg"` or bare `"x.jpg"`, per `x.imageStyle`). A new picture is an `uploads` entry referenced by exactly one op value (unreferenced upload => 422). Any other picture reference must name a file that exists at the draft head.
* Limits: ops <= 200; uploads <= 4; one upload <= 4 MB decoded (the overlay re-encodes to <= 1.5 MB, <= 2400 px long side, which also strips EXIF); strings per `schema.limits`; JSON depth <= 20.
* Idempotency: the key is written as commit trailer `Studio-Idempotency: <key>`; a repeat with the same key and user returns the original result, HTTP 200, `"replayed": true` (lookback 30 commits).
* Only uploads create files (under `images/`). An existing `images/` file is never overwritten (different bytes => `422 image` "pick another file name"; identical bytes => accepted no-op). No new data files, no new pages (Decap keeps that), no file deletion.
* Free text (title, values) is data: control characters stripped and `@` neutralised (`@` + zero-width space) wherever it is written into PR text.
* Response `201` (new) / `200` (update, replay): `{ "draft": Draft, "changes": [Change], "replayed": false, "warnings": [Problem] }` (shapes in 7.4).

## 6. Validation pipeline (unit B): `studio/validate`

`validatePatch(ctx, patch) -> { ok, problems: Problem[], warnings: Problem[], files: Map<path, {before, after}>, changes: Change[] }`;
`ctx = { schema, readText(path), hasFile(path), reservedIds: Set, now }` (the Git provider supplies the readers; tests supply a Map). Pure and portable.
Stages run in order; a stage collects all its problems, then validation stops:

1. **Envelope:** content type, size, JSON depth, unknown top-level keys rejected, counts, op names, op keys (`op,file,path,from,value,expect` only), `idempotencyKey` UUID, shas 40-hex.
2. **Scope** (`scope.js` = the ONLY definition of what may change; also imported by every GitProvider and the CI guard):
```
data:   ^src/_data/[a-z0-9-]+\.json$   and the stem is a key of schema.files (file must exist at the head)
pages:  ^src/pages/[a-z0-9-]+\.md$     and the file exists at the head
images: ^images/[A-Za-z0-9][A-Za-z0-9._-]{0,79}\.(jpg|jpeg|png|webp|gif|avif|svg)$     (upload targets only)
```
   Anything else (`.js .njk .yml .toml`, `package*.json`, `.github/**`, `cms/**`, `lib/**`, `scripts/**`, `studio/**`, dotfiles, `..`, `\`, `%`, leading `/`, NUL, case-fold collisions) => `422 path_forbidden`. Exact string match on the normalised form.
3. **Pointers:** RFC 6901 parse; reject `__proto__`, `constructor`, `prototype` segments; `-` only as the last segment of `add`; canonical decimal indexes; the pointer must `resolve()` in the schema (unknown key => `unknown_field`).
4. **Apply** to a `structuredClone` with RFC 6902 semantics, restricted: `move` only reorders inside ONE array (both indexes in range); `add` only into a schema list (item must be complete and valid; typed lists need the `type` key) or an absent optional key; `remove` only a list item (respecting `min`) or an optional key (removing a `required` field => `422 required`); `replace` only an existing value; `value` must be plain JSON.
5. **Field validation of every touched file in full** (not just touched pointers) in `fields.js`, walking the schema with the document like `scripts/lib/cmsconfig.js` does for `check:cms` (reuse or port its `alignData`/`listItemFields`). `studio/guards/check-validator-parity.js` (B) proves the validator accepts every current repo file and agrees with `check:cms` on 30 mutated copies. Per widget:
   * string/text/markdown: string; `\r\n`->`\n`; length <= limits (checked BEFORE regex, ReDoS cap); no NUL/C0 controls except `\n \t`; no bidi controls U+202A-202E, U+2066-2069; `required` => non-empty after trim; `pattern` via `new RegExp(source)`;
   * boolean strictly `true|false`; number finite, `min/max`, integer if `valueType:"int"`; select (each element if `multiple`) in `options[].value`; color `safeColor(v, null) === v`; image: pattern, image rules (stage 6), existence;
   * list: array, `min/max`, each item validated against `field`/`fields`/its `type`; object: plain object, no unknown keys (a key that already exists at the head and is unchanged is a warning, because `scripts/wiring-ignore.json` documents such keys); `hidden`/unknown widgets: value must equal the head's;
   * `x.rule`: `url` => `safeUrl(v) === v` (imported from `lib/rules.js`); `anchor` => empty or `/^[a-z0-9-]+$/` and not in `reservedIds`; `token` => `lib/tokens.js` `value()` returns the same number/word, within bounds; `redirect-from/to` => `CoveredRedirects.analyse(items).dropped.length === 0` (`cms/redirect-rules.js`; `ineffective` => warnings); `permalink` => unique among pages, not reserved.
   * **Problems already present at the head are warnings** (validate the head first, subtract), so an old quirk never blocks an unrelated edit.
6. **Uploads** (`images.js` over `scripts/lib/image-rules.js`, extracted by B from `scripts/check-images.js`, which then imports it back; behaviour unchanged): base64 strict (no whitespace tricks, decoded length == `size`); name grammar (scope); extension <-> magic bytes (JPEG FFD8FF, PNG 89504E47, GIF8, RIFF....WEBP, AVIF `ftypavif|avis`, SVG text) <-> `contentType`; <= 4 MB; pixel size from the header 1..8000 per side; JPEG with GPS EXIF => `422 image` ("remove location data"); SVG through `svgProblems()` (exactly check-images' rules); no overwrite (section 5).
7. **Serialise** (`serialize.js`): JSON re-printed with the file's indent (2 spaces), its original EOL (LF or CRLF) and trailing newline; page files: front matter dumped with `js-yaml` (`lineWidth: -1`, `noRefs`, block scalars `|-` for multi-line strings) + body, original EOL kept. **Round-trip law, enforced by a test over every current file: `serialize(parse(file)) === file`.** If a page file cannot satisfy it (e.g. YAML comments), B normalises that file in a separate commit, says so in Deviations, and `check:copy` must stay green.
8. **Post-conditions:** changed set non-empty (empty => `200 {"noop": true}`, no commit) and within scope; untouched files are not rewritten.
9. **`describe.js`:** each op -> `Change` using `labelFor()` (plain English; used by PR bodies, Changes panel, History).

CI is the second gate. The existing `site-checks.yml` (build + `npm run check`) runs on the PR because an App token (unlike `GITHUB_TOKEN`) triggers workflows. B adds `.github/workflows/studio-scope.yml` (action SHAs pinned exactly as in `site-checks.yml`, `permissions: contents: read`, `pull_request` on `main`, job `if: startsWith(github.head_ref, 'studio/')`) running `node studio/guards/check-scope.js --base origin/main --head HEAD`: fails if any changed path is outside `scope.js` (renames and deletions of non-image files fail). The API refuses to publish until both workflows are green.

`Problem` = `{ "code": "pattern|required|type|range|option|url|color|anchor|redirect|token|image|path_forbidden|pointer_invalid|unknown_field|too_large|min_items|max_items|permalink|encoding", "file": "src/_data/hero.json", "path": "/headlineMain", "message": "Plain English a founder can act on.", "hint": "optional", "value": "<= 80 chars of the offending value" }`.

### 7.2 Common rules
* Every response: `Content-Type: application/json; charset=utf-8`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Request-Id: <uuid>`. No cookie is ever read or set.
* Errors: `{ "error": { "code", "message", "details" }, "requestId" }`. Codes: `bad_request 400` · `unauthorized 401` (missing/invalid/expired token) · `not_invited 403` (valid user, no active role) · `forbidden 403` · `not_found 404` · `conflict 409` (details.items) · `draft_moved 409` (details.headSha) · `base_moved 409` · `not_ready 409` (details.reason `checks_pending|checks_failed|not_mergeable|draft_state|self_publish|head_changed`) · `payload_too_large 413` · `unsupported_media_type 415` · `validation_failed 422` (details.problems) · `rate_limited 429` (+`Retry-After`) · `upstream_error 502` (generic message; never a token) · `internal 500` (generic; cause only in the server log with the requestId). Unknown JSON fields => 400.
* **CORS** (`cors.js`): allowed origins are the exact strings of `STUDIO_ALLOWED_ORIGINS` (comma list; `https://...` or `http://localhost[:port]` / `127.0.0.1`) plus optionally ONE structural template `STUDIO_PREVIEW_ORIGIN_TEMPLATE`, e.g. `https://deploy-preview-{n}--coveredaccess.netlify.app`, where `{n}` matches `[0-9]{1,6}` and everything else is literal (an anchored, escaped regexp built at config time; not a wildcard: another site name, scheme or port never matches). `Access-Control-Allow-Origin` echoes the matched origin, never `*`; `Vary: Origin`; `Allow-Headers: Authorization, Content-Type, Idempotency-Key`; `Allow-Methods: GET, POST, PUT, DELETE, OPTIONS`; `Max-Age: 600`; NO `Allow-Credentials`. A non-allowed origin gets no CORS headers and, on state-changing methods, `403 forbidden`.
* **CSRF defence:** the only credential is `Authorization: Bearer <jwt>` (a cross-site form or image cannot set it); POST/PUT/DELETE require `Content-Type: application/json` (forces a preflight) and an allowed `Origin` (absent Origin accepted only with `STUDIO_ALLOW_NO_ORIGIN=1`, set by tests/dev).
* **Rate limits** (`limiter.take(key, {limit, windowMs}) -> {ok, retryAfterSec}`; default in-memory sliding window per runtime instance, documented as best-effort on serverless): unauthenticated 30/min per IP; failed auth 10/min per IP; per user: reads 120/min, writes 20/10 min, publish 10/10 min, restore 10/hour, admin 30/10 min. Client IP is passed by the adapter in header `x-studio-client-ip`; the handler deletes any inbound header of that name before trusting it.
* **Audit** (`AuditSink.write(entry)`; sinks: console JSON line always; optional Supabase `studio_audit` insert with the user's JWT; in-memory for tests): `{ ts, requestId, actor: {id,email,role}|null, action: "auth.denied|draft.create|draft.update|draft.submit|draft.publish|draft.discard|draft.rebase|history.restore|people.upsert|validation.failed|rate.limited", target: {draftId,pr,branch,sha}, outcome: "ok|denied|invalid|conflict|error", ops: n, files: [paths], ipHash: "<16 hex of sha256(STUDIO_AUDIT_SALT + ip)>", problems: ["code@path"] }`. Never values, tokens or bodies. Git is the second trail (commit trailers `Studio-User`, `Studio-Idempotency`; PR marker). The logger redacts any key matching `/key|secret|token|authorization|pepper/i`.

### 7.3 Roles
| capability | editor | approver | admin |
|---|:-:|:-:|:-:|
| `GET /v1/me`, `/v1/history`, list/get OWN drafts | y | y | y |
| create / update / discard / rebase OWN draft, submit it, restore (opens a revert draft) | y | y | y |
| list / get ANY draft (`scope=all`) | n | y | y |
| publish (merge) a draft | n | y (not own*) | y (not own*) |
| `GET/PUT /v1/admin/people` | n | n | y |
Roles are ordered `editor < approver < admin`. No active role => `403 not_invited` everywhere except `/v1/preview-config`. *Four-eyes: nobody publishes their own draft unless `STUDIO_ALLOW_SELF_PUBLISH=1` (default off). Discarding someone else's draft: admin only. The role is looked up on EVERY request (cached <= 30 s per user id in memory), so `active=false` revokes quickly.

### 7.5 PR and commit conventions (B)
* Branch `studio/<userKey>/<slug>`; PR base `main`; created as a **draft PR**; labels `studio-draft` (always), `studio-ready` (after submit), `studio-revert` (restore); labels are created lazily (422 "already exists" is fine).
* Title `Studio: <title> (<author first name>)` (<= 90 chars). Commit message `Studio: <title>\n\n<one line per Change>\n\nStudio-User: <user uuid>\nStudio-Idempotency: <key>`; author/committer = the App bot; no emails in git history.
* PR body (generated, escaped, <= 20,000 chars):
```

```

### 7.6 Restore (D)
`services/history.js: restore(user, token, prNumber, {onConflict, idempotencyKey})`:
1. `git.getMergedPr(n)` -> merge commit `M`, first parent `P`. Only PRs History lists qualify (`404` otherwise).
2. For each in-scope file changed between `P` and `M`: parse both, compute the pointer-level diff, invert it into ops with `expect` = the value `M` has (`invertDiff(before=P, after=M)`; pure, in `history-diff.js`). Images that PR added stay in `images/` (harmless); images it replaced are referenced again.
3. Compare each `expect` with CURRENT main: mismatch => `abort` -> 409 `conflict`; `skip` -> drop the op and list it in `skipped`.
4. Call `services/drafts.createFromOps({ user, token, title: 'Restore: undo "<title>" (#N)', ops, uploads: [], labels: ["studio-draft","studio-revert"], revertOf: N, idempotencyKey }) -> Promise<{draft, changes, warnings}>` (B must export exactly this); it runs the SAME validation pipeline. An approver publishes the revert like any draft.
`invertDiff` is tested against fixtures with list reorders, section hides, image swaps, page body edits and added/removed list items.

### 8.2 Implementations
* `git/github.js` (portable `fetch`): App JWT (RS256 via WebCrypto, `iss`=app id, 9-minute life) -> `POST /app/installations/{id}/access_tokens` with `{"permissions":{"contents":"write","pull_requests":"write","issues":"write","checks":"read","statuses":"read","metadata":"read"}}`, cached until 5 min before expiry. Headers `X-GitHub-Api-Version: 2022-11-28`, `User-Agent: covered-studio`; idempotent GETs retried twice on 5xx; failures become `upstream_error` without leaking the token. Written to the documented public API; never run against github.com by us.
* `git/mock-memory.js`: in-memory repo seeded from the working tree (`src/_data`, `src/pages`, `images`) and a given sha; the whole interface; tests set checks (`mock.setChecks(n,"success")`).
* `git/local-git.js`: real `git` in a temp clone, branches/commits via the CLI, PRs kept in a JSON file; used by `studio:e2e` to build a draft branch and run `npm run check` on it (proves validator output passes the guards and that a guard failure blocks `canPublish`).

* `auth/supabase.js` (WebCrypto): never lets the header `alg` choose the key type. `STUDIO_JWT_MODE=hs256` accepts only `HS256` (HMAC, `SUPABASE_JWT_SECRET`); `jwks` accepts only `RS256`/`ES256` with a key from `${SUPABASE_URL}/auth/v1/.well-known/jwks.json` (cached 10 min, refetched once on an unknown `kid`, rate-limited). ## 10. Overlay contract (units C and D)

### 10.1 Boot, gating, hosting
* The tag from 3.1 loads `/studio/overlay.js`: one IIFE file produced by `bundle()` = concatenation of `manifest.json` files in order, CSS wrapped as a JS string constant. No network, no `eval`.
* **Activation:** `main.js` runs only if `location.search` has `studio=1` (then `sessionStorage["covered.studio.on"]="1"`, try/catch), or that key is set, or `location.hash === "#studio"`. Otherwise it returns at once: a normal visitor of a preview sees the unmodified site. `?studio=0` clears the flag.
* **How a founder opens it:** the "Open in Studio" link in the draft PR (7.5), the preview URL + `/?studio=1`, or in dev `http://localhost:8080/?studio=1`. A small "Edit" pill appears bottom-right; the pill or `Esc`/`E` toggles Edit mode; in Browse mode the site works normally.
* **Hosting:** no separate hosting. The overlay and `content.json` are files of the preview build, same origin as the page. Only the login page is deployed separately (8.5).

### 10.2 `window.CoveredStudio` (built by C's `main.js`; D's `ext/*` use only this surface)
```
CoveredStudio = {
  version: 1,
  config: { apiBase, appUrl, contentUrl, build: {sha, branch, prNumber}, dev: boolean },
  me: null | { user: {id,email,name}, role, capabilities: {draft,publish,people} },
  mode: "browse" | "edit",
  on(event, fn) -> off(), emit(event, detail),
  api: { get(path), post(path, body), put(path, body), del(path) },   // adds the bearer; rejects with StudioError {status, code, message, details, requestId}
  schema: { raw, resolve(ref) -> {field,...}|null, label(ref), fields(ref) },
  content: { get(ref) -> current value (base + staged), base(ref), files() },
  staging: { set(ref, value, meta?), toggle(ref), move(listRef, from, to), add(listRef, item), remove(itemRef),
             setImage(ref, fileOrBlob, {alt?}) -> Promise<void>,
             list() -> [Staged], count(), discard(ref), clear(), save({title}) -> Promise<{draft, changes}> },
  drafts: { current() -> Draft|null, list(), refresh(), setCurrent(id), submit(), publish(), discard() },
  ui: { h(tag, props, ...children) -> Element,
        registerPanel({ id, title, glyph, order, minRole, render(container, studio) -> void | (() => void), onShow?, onHide? }),
        openPanel(id), closePanel(), togglePanel(id),
        registerCommand({ id, title, keywords: [], group, shortcut?, when?(studio) -> bool, run(studio) }),
        registerEmptyState(panelId, fn),       // optional hook; D tolerates its absence
        toast(message, { kind: "info|success|error", actionLabel?, onAction? }),
        confirm({ title, body, confirmLabel, danger? }) -> Promise<boolean>,
        editRef(ref),                          // scroll to the marker and open its editor, or open Fields panel focused on it
        focusTrap(el) -> release },
  util: { debounce, uuid, truncate }

```
Events (`detail` objects): `ready`, `auth:change {me}`, `mode:change {mode}`, `selection {ref|null}`, `staged:change {count}`, `draft:change {draft}`, `draft:saved {draft, changes}`, `panel:open {id}`, `panel:close {id}`, `history:restored {draft}`, `error {error}`.
`h(tag, props, ...children)` is the ONLY element factory: tag from an allow-list of ~25 HTML tags (no `script style iframe object embed link meta base`); props limited to `class id type value placeholder title role tabindex hidden disabled checked min max rows for name href target rel src alt width height open`, `aria-*`, `data-*`; handlers via `props.on = { click: fn }` (never as attributes); string children become text nodes; `href`/`src` pass only through `safeHref()` (same rules as `safeUrl`, plus `blob:` for local previews). **Editor/server text only ever reaches the DOM through `textContent`/text nodes.**

### 10.3 Behaviour (C)
* **Shadow root:** one host `<div id="covered-studio" data-studio-ui>` appended to `<body>` with an OPEN shadow root holding all chrome (panel, toolbar, toasts, popovers) and the highlight layer (absolutely positioned boxes). Site elements receive only staged-value updates and the attributes `data-studio-hidden` / `data-studio-dirty`.
* **Select:** in Edit mode marked elements show an outline + label (kind and field label). Desktop: click selects. Touch: tap selects, a second tap opens the editor; a selection toolbar (Edit, Up, Down, Hide/Show, Delete, Undo) sits above/below the element inside the viewport. Page link navigation is suppressed in Edit mode.
* **Editors:** `text`/`longtext` leaf elements (no element children): `contenteditable="plaintext-only"` in place (fallback popover if unsupported), commit on blur/Enter (text) or Ctrl/Cmd+Enter (longtext), Esc cancels. Elements with element children, and `markdown`, `link`, `color`, `image`, `toggle`, `section`, `item` use a popover/bottom sheet with real form controls: counter vs `max`, live validation from the schema (advisory; server authoritative), required alt-text prompt for a new picture (or "decorative" switch), crop-to-the-displayed-aspect-ratio with drag-to-reposition (canvas; output JPEG/WebP <= 1.5 MB, <= 2400 px), colour input + hex field (contrast hint optional via `cms/contrast.js` rules if loadable without adding third-party code), link helper ("this site / a section / a web address / email") that always writes a value matching `x.rule url`.
* **Live DOM updates for staged values (never innerHTML):** text -> `textContent`; image -> `img.src = blobUrl` (removes `srcset` and sibling `<source>` for the preview); link -> `setAttribute("href", safe)`; color -> `documentElement.style.setProperty(cssvar, hex)` when `data-cms-cssvar`; toggle -> `data-studio-hidden`; section hide -> dimmed with badge "Hidden on the live site" (stays in DOM so Undo works); markdown -> DOM unchanged, `data-studio-dirty` + badge "Updated - shows after saving". Original values are remembered for discard.
* **Panels (C):** `changes` (staged list in plain English with per-line Undo; Save draft, Send for review, Publish (approver); draft status incl. checks and preview link; Discard all), `sections` (all homepage sections from content.json including hidden ones: show/hide, move up/down, jump to), `fields` (searchable form of every schema field of the current page's file, including aria/meta ones; inline validation), `account` (who, role, sign out). D adds `history`, `help`.
* **Staging store:** `localStorage["covered.studio.v1:<apiHost>:<userId>:<draftKey>"]` (`draftKey` = draft id or `new:<baseSha>`) = `{ v:1, ops:[...], t }`; every storage access in try/catch, quota errors tolerated, UI works without storage; image blobs in IndexedDB under the same key, best effort (lost on reload => that op is dropped with a toast). On load, reconcile with content.json: an op whose `expect` no longer equals the base value is marked "main changed" for review.
* **Save flow:** build the patch from `staging.list()` (ops with `expect`, uploads from images; a new `idempotencyKey` per Save click, reused when retrying that same click), `POST /v1/drafts` (with `draftId` + `expectedHeadSha` when a draft is current). `201/200`: clear staged, `draft:saved`, toast with link, poll `GET /v1/drafts/:id` every 15 s (max 10 min, only while the Changes panel is open) for checks and preview URL. `422`: map each Problem (file+path) back to its element/field (red outline + message in the panel, nothing lost). `409 conflict`: "Someone changed these since you started": per item Keep mine / Take theirs. `base_moved`/`draft_moved`: Refresh (reload content.json) or `POST .../rebase`. `401`: rerun the token broker once, then show sign-in. `429`: wait `Retry-After`. Offline (`fetch` rejects): keep staging, banner "Saved on this device - will send when you are back online", retry button.
* **Accessibility of the overlay itself:** real `<button>/<input>/<label>` controls; panel `role="complementary"` with a label; popovers/sheets `role="dialog" aria-modal="true"` with focus trap and focus return; a visually hidden `aria-live="polite"` region announces toasts, saves and validation errors; focus rings >= 3:1; chrome text contrast >= 4.5:1 in light and dark (`prefers-color-scheme`); touch targets >= 44x44 px on coarse pointers; `prefers-reduced-motion` honoured; no keyboard traps; usable at 200% zoom. Keys: `Ctrl/Cmd+K` palette, `Ctrl/Cmd+S` Save draft, `Esc` back out one level, `E` toggle Edit mode (no field focused), `]` / `[` next/previous marked element, `Enter` open the editor of the selection, `Alt+ArrowUp/Down` move a selected section/item, `?` Help, `Ctrl/Cmd+Z` / `Shift+Ctrl/Cmd+Z` undo/redo within staging.
* **Mobile (< 760 px or coarse pointer):** panels become a bottom sheet (<= 70% height, drag handle, `visualViewport`-aware so the keyboard does not cover the editor); pill FAB bottom-right with a count badge; selection toolbar as a bottom action bar; nothing needs hover. This is how "hide a section from a phone" works (D9).
* **No third parties:** no CDN, no web fonts (`system-ui`), no analytics, no `fetch` outside `apiBase`, `appUrl`, and the page's own origin.

## 12. Security checklist (acceptance for the phase)

1. API accepts only data patches: `scope.js` is the one definition, used by the validator, every GitProvider and CI (`studio-scope.yml`); a selftest proves each of the three notices `package.json`.
2. Every value is validated by the CMS rules (schema) and the code rules (shared modules) BEFORE commit, then built and guarded in CI before merge; `publish` needs both workflows green and the head sha the approver saw.
3. No secret in any file; tests generate keys; nothing reads `.env` files.
4. Overlay: static ban list (9, `check-overlay`), `h()` the only element factory, text via `textContent`, no HTML from server or editor text, no third-party host.
5. Production HTML byte-identical (3.4e); no Studio path or attribute in a normal build.
6. Dev stub unusable in production (8.4); mixed configs refused at start-up (7.7).
7. A stolen editor token can draft, discard and restore inside the data scope under rate limits; it cannot publish, read others' drafts or touch code. A stolen approver token can also publish drafts that passed CI. Tokens live 1 h (Supabase default) and sit in memory only; `active=false` revokes within 30 s.
8. Hostile page: no cookies, exact-origin CORS, JSON preflight, bearer in header only, `postMessage` origin checks both ways, login page refuses unknown `origin`.
